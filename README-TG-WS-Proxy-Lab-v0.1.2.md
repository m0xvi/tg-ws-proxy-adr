# TG WS Proxy Lab 0.1.2

Диагностический GPLv3-форк `amurcanov/tg-ws-proxy-android` для проверки различий между мобильными сетями до изменения транспортного ядра.

## Назначение первой версии

Версия 0.1.2 не обещает новый способ обхода фильтрации. Она собирает воспроизводимую матрицу доступности:

1. контрольный TLS до `ya.ru`;
2. Telegram DC2 WebSocket через DNS;
3. Telegram DC2 WebSocket через фиксированный IP с корректным SNI;
4. Telegram DC4 WebSocket через фиксированный IP с корректным SNI;
5. три общих Cloudflare WebSocket-маршрута;
6. передача 64 КиБ через Cloudflare;
7. необязательный пользовательский WSS Worker/VPS endpoint.

Каждая проверка разделяет стадии DNS, TCP/443, TLS и HTTP WebSocket Upgrade. IPv4 и IPv6 проверяются отдельно, если оба семейства доступны.

## Почему используется системный TLS Android

Текущее Rust-ядро прокси использует `rustls`. Диагностические запросы выполняются через системный `SSLSocket` Android. Если Android WebSocket проходит, а Rust-ядро на той же сети получает timeout/reset, это указывает не на недоступность IP как такового, а на возможную зависимость от реализации TLS, ClientHello/fingerprint, таймингов либо WebSocket-кода.

## Установка

- APK: `TG-WS-Proxy-Lab-v0.1.2-universal.apk`
- Android: 7.0 и новее (minSdk 24)
- ABI: arm64-v8a и armeabi-v7a
- Package ID: `com.tgwsproxy.networklab`
- Подпись: стандартный Android debug certificate

Отдельный Package ID позволяет установить Lab рядом с оригинальным приложением. Не запускайте одновременно два локальных прокси на одном порту.

## Первый тест: Билайн, Калининград

1. Остановить VPN, AdGuard/Blokada и другие приложения на базе `VpnService`.
2. Отключить Wi-Fi, оставить мобильную сеть Билайн.
3. Открыть вкладку **Тест**.
4. Поле своего WSS оставить пустым.
5. Нажать **Начать тест** и дождаться завершения.
6. Нажать кнопку копирования и сохранить отчёт.
7. Повторить тест через Wi-Fi для контрольного сравнения.
8. Передать оба отчёта разработчику вручную.

Если имеется собственный Worker/VPS, в поле можно указать полный URL вида:

```text
wss://proxy.example.com/apiws
```

## Приватность

Приложение ничего не загружает автоматически. Отчёт создаётся локально и передаётся только после нажатия «Копировать» или «Поделиться».

В отчёт входят:

- модель устройства, Android и ABI;
- тип сети и имя оператора, доступное через Android;
- наличие IPv4/IPv6, VPN и Private DNS;
- адреса тестируемых серверов, к которым реально подключился Android;
- стадии ошибок и времена подключения.

Локальный и публичный IP-адрес абонента намеренно не сохраняются.

## Интерпретация

- **TCP FAIL** — маршрутизация, IP-фильтрация или временное ограничение мобильной сети.
- **TCP OK + TLS FAIL** — возможна фильтрация SNI/TLS/fingerprint либо несовместимость TLS.
- **TLS OK + WebSocket не 101** — фильтрация Upgrade/path/domain, redirect, rate limit или неисправность endpoint.
- **Android WS PASS, Rust proxy timeout** — приоритет следующего этапа: альтернативный транспорт на системном Android TLS/Conscrypt.
- **Cloudflare 64 KiB заметно короче 65536 байт** — возможен ранний обрыв/ограничение передачи.

## Следующие этапы

После получения отчётов:

1. выбрать проходящие маршруты на Билайне;
2. добавить policy/failover `direct -> Worker -> private relay`;
3. сравнить `rustls` и Android/Conscrypt на одинаковом endpoint;
4. добавить собственный relay-компонент и health-check;
5. протестировать рабочий MTProto-трафик и медиа, а не только handshake.
